# MED: путь от одного VPS к распределённым серверам

## Сегодня: single-host
MED API, Dashboard, Collector, Discovery используют один Docker Compose и общий named volume `med_history`. SQLite — только локальный способ хранения. В `compose.yml` добавлено `MED_TOPOLOGY=single-host`. `deployment.py` явно запрещает объявлять неподдерживаемый распределённый режим.

## Этап A: доказать работающий MVP
- На тестовом VPS выполнить `docker compose config`, `docker compose up -d --build`, `docker compose ps`.
- Проверить `/healthz`, `/integration/status`, поиск, историю NCT и публикацию/чтение документов.
- Прогнать все unit-тесты, затем end-to-end сценарий на синтетических/публичных данных.
- Настроить резервное копирование SQLite при согласованной процедуре и восстановление на отдельной тестовой площадке.

## Этап B: отделить storage
- Выделить единый слой доступа к данным для исследований, документов, журналов и Discovery.
- Написать миграции схем, перенос данных из SQLite в PostgreSQL, проверку контрольных сумм и количества записей.
- Для тяжёлых файлов и выгрузок использовать объектное хранилище, сохранять в БД идентификаторы, версии, SHA-256 и ссылки на оригинальные источники.
- Вынести пароли/ключи из репозитория в переменные окружения/секреты; включить шифрование транспорта.

## Этап C: отдельные хосты
- MED API и Dashboard → отдельный хост; Collector/Discovery → отдельный хост; PostgreSQL и файловое хранилище → выделенные сервисы.
- Обращение к данным по защищённым сетевым интерфейсам, без общего SQLite-файла и без Docker volume между серверами.
- Отдельные учётные данные, мониторинг здоровья, ограничение доступа, таймауты и повторы.
- Проверить синхронность версий схемы, отсутствие дублей при повторах, восстановление при обрыве связи.

## Этап D: интеграция GENESIS
- L2 выступает контролируемым клиентом MED API; Android обращается к CORE/L2, а не напрямую к MED.
- Документы предоставляются через `GET /documents` и `GET /documents/{document_id}`; публикация через `POST /documents/research` доступна только разрешённому сервису.
- Уточнить договор API, сервисную аутентификацию, авторизацию по документам, трассировку запросов и квоты.
- Продемонстрировать сквозной сценарий: источник → MED Analytics → документ MED → L2/CORE → Android «Сервисы → Документы».

## Обязательный критерий переноса
Миграция завершена только после сверки количества документов и версий, контрольных сумм, полноценного восстановления из резервной копии, проверки разграничения доступа и повторения end-to-end теста.

**Текущее состояние:** распределённый режим не реализован. Файл описывает целевой план, а не уже готовые функции.
